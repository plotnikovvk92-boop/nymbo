# Нямбо: исправленная копия для проверки перед выпуском

Источник — приложенный пользователем архив, а не содержимое Beget. `.env`, клиентские базы и SSH-ключи в этот комплект не входят. Никаких файлов Beget этой сессией не изменено.

Полные файлы находятся в `gymochka_app/`, Passenger — в `passenger_wsgi.py`, регрессионные тесты — в `tests/`, диагностика и бэкап/откат — в `tools/`. `reports/AUDIT_RU.md` описывает результаты и оставшиеся блокеры. Юридические документы являются обновлёнными черновиками, не опубликованными документами.

## Локальная проверка

Из корня распакованного комплекта:

1. `python3.10 -m venv .venv`
2. `.venv/bin/python -m pip install -r requirements-python310.lock.txt`
3. `.venv/bin/python tests/test_regression.py`

Тесты принудительно используют фиктивную конфигурацию, временные БД, имитацию Telegram и HTTP API на loopback. Для проверки текста PDF нужен `pdftotext` (poppler-utils). Они не запускают polling, не регистрируют webhook и не обращаются в реальную ЮKassa. Для тестов не нужен рабочий `.env`.

## Порядок двух серверных установок

Каталоги нельзя выбирать по названию. Сначала получить диагностику `tools/diagnose_beget.py` и подтвердить каталог теста, каталог production, отдельные токены/БД, фактический Passenger entrypoint каждого домена, Python, а также режим магазина. Приведённый в архиве APP_DIR доказывает только настройку приложенного файла, не назначение серверной среды.

1. Сохранить комплект вне публичного каталога сайта. Запускать диагностику интерпретатором существующего venv, не `bot.py`.
2. Выбрать только подтверждённое тестовое приложение. Выделить venv для установки, если нынешний venv общий с production: менять общие зависимости до теста production нельзя. Python/Passenger interpreter должен быть подтверждён по настройкам Beget, не предполагаться по имени папки.
3. Для тестового приложения создать приватный бэкап: `python tools/release_manager.py backup --app APP --db DB --entry ENTRY --backup BACKUP`. APP, DB, ENTRY — реальные абсолютные пути из диагностики; BACKUP — новый каталог вне публичного web-root, например под `/home/p/plotnixu/.nyambo-backups/`. Скрипт копирует изменяемые исходники, приватно сохраняет `.env`, Passenger entrypoint и делает согласованный SQLite backup через SQLite API с WAL и `quick_check`.
4. Установить зависимости в выбранный venv и выполнить регрессию на временной БД. Ничего не тестировать на данных клиентов. Проверить публичные документы и конфигурацию отдельно. Файл `requirements-python310.lock.txt` фиксирует проверенные локально версии; совместимость бинарных пакетов с libc Beget ещё не установлена.
5. Остановить **только выбранное** приложение средствами Beget на короткое окно установки. Учесть завершение уже выполняющихся запросов. Перед заменой повторить бэкап SQLite и исходников в новый каталог. `--service-stopped` — явное подтверждение реально выполненной остановки, а не команда остановки.
6. Выполнить `python tools/release_manager.py install --app APP --entry ENTRY --backup BACKUP --service-stopped`. Скрипт проверяет соответствие бэкапа выбранному приложению, проверяет синтаксис, меняет только полные Python-файлы, requirements и выбранный Passenger entrypoint, подставляя подтверждённый APP_DIR. Он сохраняет `.env`, БД, шрифты, опубликованные юридические файлы; перезапуск не делает. Отдельно проверить `.env`: старое SERVICE_NAME может перекрывать новый default «Нямбо». Поддержка — @gymochka_admin.
7. Перезапустить выбранное приложение средствами Beget. Не запускать `bot.py` без `--webhook`, не запускать второй polling, не вызывать deleteWebhook/setWebhook. Новый startup сверяет существующий webhook с WEBHOOK_URL + /webhook и останавливается при несовпадении, вместо переключения webhook.
8. В тестовом боте пройти анкету → redirect-платёж → webhook/GET → автоматический доступ → меню → рецепты → покупки → PDF. Проверить TEST_MODE/skip_pay отдельно. Согласовать/проверить живучесть Passenger worker в простое: встроенный цикл не выполняется, если хостинг выгрузил весь процесс. При выгрузке нужен согласованный scheduler/cron или поддерживаемая настройка постоянно работающего worker. Cron этим комплектом не установлен.
9. Только после подтверждения тестового пути повторить пункты 2–7 для production с **его** venv/конфигурацией/БД/entrypoint. Не копировать тестовые `.env` или базы. Не заменять корневой passenger_wsgi.py, если он обслуживает другой домен/среду.
10. Рабочий магазин должен быть подтверждён по кабинету и проверенному API-платежу: test=false, recipient.account_id равен рабочему shop ID. Проверить порядок чеков и налоговый статус. Только затем пользователь самостоятельно оплачивает 89 ₽; проверить автоматическую выдачу доступа и весь клиентский путь, включая PDF. Return URL доступа не выдаёт. Установку рабочего магазина и реальный платёж здесь ещё не выполняли.

На сервере команды пользователю даются по одному конкретному шагу после получения реальных путей. APP/DB/ENTRY/BACKUP — обозначения в инструкции; не вставляйте их буквально в терминал.

## Откат

Остановить только изменённое приложение, затем `python tools/release_manager.py rollback --backup BACKUP --service-stopped`. Восстанавливаются старые исходники и его Passenger entrypoint. Живая БД и `.env` сохраняются, поэтому новые оплаты/клиентские данные после бэкапа не теряются. Новые вспомогательные модули остаются, но старые файлы их не импортируют. Аддитивные таблицы/колонки совместимы со старой схемой. Перед возобновлением оплаты учесть, что возвращаются также старые ошибки; безопаснее временно оставить оплату недоступной и расследовать сбой.

`database.sqlite3` в бэкапе — для аварийного восстановления, не для обычного отката кода. Восстановление БД требует остановки всех писателей и сверки платежей после времени снимка; автоматически скрипт БД не заменяет, WAL/SHM не удаляет. Старый venv сохранять до завершения проверки нового; переключение Passenger interpreter и его откат зависят от подтверждённой конфигурации Beget.

## SSH

В текущей облачной среде подготовлен отдельный ключ и отдельная конфигурация OpenSSH. Секретный ключ сюда не включён. Подключение не установлено: внешний DNS недоступен, прямое соединение с предоставленным IP на 22 отвергается, сетевой прокси выдаёт 403 на CONNECT к хосту. Дополнительно проверена политика текущей среды: tcp_network_access не содержит разрешённых доменов или IP. Доступ через HTTP и доступ через SSH/TCP — разные настройки. Настройка прямого доступа отложена по просьбе пользователя; установка на Beget ещё не выполнена.

Первичный отпечаток из предупреждения ssh не является независимым подтверждением. Сверить ED25519 SHA256 через поддержку Beget либо уже доверенную консоль Beget (`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`). Только после сравнения полученного ключа записать его в отдельный known_hosts, сохраняя StrictHostKeyChecking=yes. Проверка подключения: `ssh -F /workspace/.nyambo-ssh/config beget-nyambo 'id -un; pwd'`. Эту проверку на сервере здесь ещё не удалось выполнить.

Для отзыва доступа удалить **только** публичный ключ с комментарием `codex-nyambo-beget-2026-10-10` из SSH-ключей Beget/authorized_keys. Не удалять остальные ключи.
